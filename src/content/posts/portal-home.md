首页是这个主题里唯一「一屏里塞很多信息」的页面。它不是普通的卡片流，而是分成三块的门户版式：

| 区块 | 内容 | 由谁控制 |
| --- | --- | --- |
| ① 顶部置顶 | 左侧纯图片轮播 + 右侧置顶文章列表 | `portal.featured` / `heroAutoplay` |
| ② 中间分类列表 | 你挑选的分类，每个可单独选卡片或列表 | `portal.categories[]` |
| ③ 底部最新 | 不分类别，纯文字列表 | `portal.latest` |

这三块全部由 `src/config/user/content.ts` 的 `index.portal` 决定。页面本身（`src/pages/index.astro`）只是照着配置渲染，**想调密度或顺序，改配置就行，不用碰页面代码**。

## 一份完整的配置

```ts
index: {
  portal: {
    featured: 5,            // 置顶取前 5 篇（同时驱动左图轮播 + 右列表）
    heroAutoplay: 5000,     // 轮播每 5 秒切一张；0 = 不自动播放
    cardsPerRow: 4,         // 卡片式每行固定 4 张（全局统一）
    categories: [
      { name: '指南', layout: 'card', rows: 2 },   // 卡片，两行 = 8 张
      { name: '实现', layout: 'card', rows: 1 },   // 卡片，一行 = 4 张
      { name: '随笔', layout: 'list', cols: 2 },   // 文字列表，两列
      { name: '使用', layout: 'list', cols: 1 },   // 文字列表，单列
    ],
    latest: { count: 10, cols: 2 },                // 底部最新 10 篇、两列
  },
}
```

## 置顶：featured

`featured` 是「取前几篇文章」。它同时喂给两个地方 —— 左边的图片轮播、右边的文字列表 —— 所以两边永远是同一批文章。

排序沿用全站的「置顶优先」规则：`sticky: true` 的文章排在最前，其余按日期倒序。想让某篇露脸，在它的 front matter 里写 `sticky: true`。

`heroAutoplay` 是轮播间隔（毫秒）。设成 `0` 就不自动切换，只留底部指示条手动点 —— 内容少、或者不想让页面自己动的时候，把它关掉。

轮播在鼠标悬停或键盘焦点进入时自动暂停；读者的系统开了「减少动态效果」时也不会自动播放，指示条切换照常可用。

触屏上除了点指示条，还可以**左右滑动**切图：横滑超过 40px 且以横向为主才切，纵向滑动仍然滚页面。滑完之后浏览器补的那次点击会被拦掉，不会顺手打开当前这张的链接。指示条是几根 14×3px 的小白棒，当前那根拉长到 26px、变成实白；触屏上略放大，命中区用伪元素撑到 24px 且两两不重叠。这一段只在手机上**也显示门户版式**时才有意义（即 `mobileFeed.enable: false`）—— 默认手机会换成一屏一张的卡片流，见下面的[手机端](#手机端单列卡片流)。

## 卡片每行几个：cardsPerRow

卡片式统一按这个值排行，它只影响 `layout: 'card'` 的分类，列表式不读它。

改这里等于全站生效：值会被写进一个 CSS 变量，网格按它算列数。桌面按你配的值；手机默认不显示门户，只有把 `mobileFeed.enable` 关掉、手机也走门户时才会降到 2 列（4 列在手机上每张只剩几十像素，封面和标题都糊）。

## 分类列表：categories

这是一个**有序数组**，从上到下按你写的顺序展示。两条规则要记住：

- 只列想展示的分类；不在数组里的分类不会出现在首页（但仍有自己的分类页）。
- `name` 必须和文章 front matter 的 `categories` **完全一致**（大小写、空格都算）。写错的话，这一块会被静默跳过 —— 构建时会打印一行提醒你哪个名字对不上。

每个分类独立选版式：

| 版式 | 关键字段 | 展示篇数 |
| --- | --- | --- |
| `layout: 'card'` | `rows`（显示几行，默认 1） | `rows × cardsPerRow` |
| `layout: 'list'` | `cols`（几列，1 或 2，默认 1） | `cols × 5` |

想多展示几篇、又不想改版式，可以加 `count` 直接覆盖篇数，比如 `{ name: '指南', layout: 'card', rows: 2, count: 6 }` 就只取 6 篇。分类下文章不够时按实际数量显示，不会留空。

数组留空（默认值）时退回「兜底模式」：按文章数取前 8 个分类、全部卡片一行。适合还没想好首页排布、先让它有内容。

## 底部最新：latest

不分类别，按时间倒序列出最新 N 篇，纯文字、可两列。它是「我就想快速扫一眼最近写了什么」的入口，右上角的「更多」跳到 `/archives/`。

## 手机端：单列卡片流

门户版式是给大屏的。手机宽度下它只能靠缩 —— 每行 4 张卡片降成 2 张、摘要只露得出几个字、置顶列表挤在图片下面。所以窄屏默认换成原版 Fluid 的首页样子：**一屏一张卡，封面在上，标题、三行摘要、日期 / 分类 / 标签在下**。

| 视口宽度 | 显示什么 |
| --- | --- |
| ≥ 768px | 门户版式（置顶 + 分类分区 + 最新） |
| ≤ 767px | 单列卡片流，底部一个「全部文章」按钮 |

开关和篇数在同一个文件里，和 `portal` 平级：

```ts
index: {
  mobileFeed: {
    enable: true,   // false = 手机也用门户版式
    count: 10,      // 卡片流展示几篇；其余走「全部文章 → /archives/」
  },
}
```

两套版式都渲染进 HTML，由一条媒体查询互斥显示，所以**桌面端一点都不受影响**；被藏起来那份里的图片是懒加载，浏览器不会为一个 `display: none` 的块去下载它们。首页没有分页，卡片流只给前 `count` 篇，末尾的「全部文章」进 `/archives/`。

`count` 写 0 会在构建期报错 —— 那样手机首页只剩一个按钮，看着像坏了。

## 改坏了会怎样

配置里的数值都有合法区间，越界不会让构建失败，但会让版式静默塌掉 —— 比如 `cardsPerRow: 0` 会让卡片网格失效、整行掉成单列。所以 `npm run build` 时会做一遍体检，把这类「看着不对但没报错」的值直接点出来。

## 和 older 分页说再见

门户首页是固定区块，没有「下一页」。全量浏览交给 `/archives/`，所以旧的 `/page/N/` 已经被移除；如果你有历史链接，`_redirects` 会把它们 301 到归档页，不会 404。
