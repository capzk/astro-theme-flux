## 怎么读

- 想知道**某个奇怪写法为什么是这样**（比如轮播为什么不给暂停按钮、`_headers` 为什么每条都先 `! Cache-Control`）→ 先在 `待修复项.md` 里搜关键词。
- 想复核**性能结论还成不成立** → 看 `性能审查-2026-11-02.md` 顶部的落地状态表，再对照当前构建产物。
- 想知道**某一版改了什么** → CHANGELOG；这里的报告只解释「为什么」。

## 维护约定

- 报告（`*审查-*.md`）**写完即定稿**，后续发现的问题写进 `待修复项.md`，不要回头改报告 ——
  否则「当时是怎么判断的」就丢了。
- `待修复项.md` 的条目号只增不改；修复后在概览表里标状态，并在文末按日期记一段
  「修复记录（YYYY-MM-DD）」，写清改了什么、怎么验证的。
- 一份新报告的文件名固定为 `<主题>审查-YYYY-MM-DD.md`，并补进上面那张表。
